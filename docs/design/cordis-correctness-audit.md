## 已修复问题

前端共八组：

1. 工作台和重跑在提交中、结果未确认时仍可切换 workflow，导致持有提交 ID 的表单卸载。现在锁定流程选择，保留原 ID 的查询与处理入口。
2. 重跑失败后配置冻结且没有清理入口。现在支持显式查询创建结果、使用同一 ID 再提交，以及清理未创建任务的导入残留后修改配置。
3. 查询路径改变后继续显示上一查询的数据或错误。现在按路径隔离结果，筛选失败不会呈现旧筛选内容。
4. 删除任务前，原生音频组件卸载未主动释放读取。现在与视频共用媒体释放逻辑，暂停并清除源地址。
5. 先注册的参数路由会遮蔽后安装插件的静态路由，例如 `/tasks/:id` 遮蔽 `/tasks/help`。现在优先匹配更具体的静态路径段。
6. 连接保存期间继续编辑可能被响应清空新密钥，编辑后仍显示“已保存”。现在保存期间锁定输入，编辑后清除已保存状态，成功后刷新 provider 目录。
7. 本地化编辑器的并行 catalog 请求可能用旧快照覆盖刚刷新的 Runtime 能力。现在直接使用 `/api/v2/runtime` 返回的能力与设备信息。
8. 设置页刷新只读取 catalog 快照。现在先执行 Runtime 探测，成功后刷新目录；探测期间禁止重复点击，失败明确显示，等待用户操作。

Host、HTTP 与 workflow：

- 修复跨扩展依赖装配与异步卸载，扩展安装、启停和卸载修改互斥。
- 非对象 JSON 返回 400；补充真实媒体探测并由 workflow 检查媒体能力。
- 修复具名输入重复、超限上传挂起、缺失 multipart boundary、上传流截断及仅含 metadata 的请求未占用导入目录等问题。无文件 workflow 同样遵守 fresh 目录和残留检查。
- 任务执行器失效后，健康接口返回 503；带时区偏移的轮询时间统一转成 UTC，避免 SQLite 字符串比较造成错误等待。
- 修复 `defaults=null` 时目录描述递归，通过 `listProviders` 读取 provider 列表。

Python 执行与结果处理：

- 修复 ACK 与取消之间的竞态。
- 设置校验失败返回 422，traceback 不暴露输入值。
- 拒绝格式错误的 ASR 词元，对外部对齐结果进行语义校验。
- 已收到的原始供应商响应保留为执行证据。
