# YouDub MVP 开发计划

2026-09-22。开发分支：`codex/mvp-mainline`；起点：`main` 的 `0f6c75935e7a208c4b8ea56140e31c5316953fec`。

## 持续目标

依据[已确认的接口与流程主干](youdub-desktop-v0.1.md)，在现有 YouDub-webui 中完成单视频 MVP：本地导入 → ASR → 翻译 → 字幕或配音 → 预览和下载。先让流程和接口可用，再根据真实视频效果优化。每个可验证增量独立提交，分批推送开发分支。

业务边界为一个本机后端、SQLite、任务管理/视频处理/模型适配三个模块，以及 `tasks`、`settings` 两张业务表。复用现有登录、Web 界面和已验证的媒体函数。任务创建时固定配置，单次执行一个 Task，其它任务排队。

开发契约：[OpenAPI](youdub-api-v0.1.openapi.json)、[新库 DDL](youdub-schema-v0.1.sql)、[状态图](youdub-task-state-v0.1.mmd)、[飞书评审稿](https://my.feishu.cn/docx/Nm3bdG4CGoDu6gxvMSmcOp43nWd)。

## 代码改造落点

当前 `backend/app/main.py` 已有上传、任务查询、认证和视频下载入口；`worker.py` 已有单线程 FIFO；`pipeline.py` 与 `adapters/` 提供媒体函数。前端复用 `apps/web/src/lib/api.ts`、任务列表、任务详情和设置界面。

优先改造以下实际差异：

- 当前流水线使用九阶段和 `task_stages`；新业务链使用七阶段与 Task 中的当前执行状态，旧库保留原语义，新库按 DDL 建立。
- 当前阶段进度使用 0–100；新接口统一使用 0–1 或 null。
- 当前翻译步骤读取执行时的默认设置；新任务使用创建时的配置快照。
- 新 ASR 链保留原始分段、文本、顺序和时间戳，独立计算配音时间轴。
- 单任务执行必须覆盖本机业务入口，避免旧入口和新入口分别启动执行器造成并行。

独立 [youdub-backend](https://github.com/liuzhao1225/youdub-backend) 的阶段输入输出、ASR 原始 utterances 和外部请求提交/查询作为媒体处理参考。具体已核对范围见[主干设计的参考依据](youdub-desktop-v0.1.md#参考依据与接口附件)。

## 开发与推送规则

1. 一个提交完成一个可说明的行为变化，代码与必要的验证一起提交。提交说明和后续 PR 说明使用中文。
2. 每个增量完成后运行与改动相关的必要检查，通过后立即普通推送 `origin/codex/mvp-mainline`，核对远端提交 SHA。保持提交历史，不强制推送。
3. 接口/状态/媒体时间轴变化应有相应契约或行为验证；界面变化运行关联检查并查看实际页面。纯文档改动做内容与差异核对。
4. 在阶段联调和最终交付时运行现有必要质量检查。真实模型能力必须由真实结果证明；Mock 仅用于测试和联调，明确标记。
5. 失败立即报告原始原因并在原处修正；接口不可用、模型缺失或 Windows 未验收时明确记录状态。
6. 每次更新计划保留已完成项，并附上新增提交、推送结果、已验证行为和下一步。

## 联调依赖与范围

实现期间先核对已有可用模型、语言、声音方式、FFmpeg 和运行环境。当前默认验证方向为英语视频到中文字幕/配音；模型以实际配置和能力核对结果为准。VoxCPM2 的正式远端接口规范尚未提供，取得规范并联调前保持不可用。

真实模型或 Windows 参考机器暂不可用时，继续完成不依赖它们的接口、任务链和页面开发，并单独记录尚未完成的真实验收。调用已有模型与本地配置时不将密钥、用户视频或模型权重写入 Git。

本轮后置：逐句重做、缓存复用、多任务性能、模型常驻/加速、广告裁剪、整体倍速、投稿、复杂恢复矩阵和具体案例的算法调优。桌面宿主和安装包方案在主流程实测后确定。部署和合并由后续任务明确安排。
